Algen Agent Tools · v0.2.0a11

Typed tools for agents. Governed by default.

Curated connectors for agents built on Algen Agent Runtime. Each connector is a set of narrow, typed actions with a declared side effect, permission and approval rule, registered as a Runtime plugin so Studio can list it before anything runs.

Where Tools fits#

Runtime runs agents; Tools gives them safe ways to touch the outside world. A connector's tools reach Runtime through a declared plugin, Studio lists them from algen-agent-runtime describe, and the same agent.yaml deploys anywhere.

Why a separate package#

Narrow, typed actions

No free-form SQL, URLs, shell commands or vendor request bodies. The model fills typed fields; the connector does the rest.

Visible before it runs

Every tool's side effect, permission, timeout and environment variables appear in describe and Studio without running project code.

MCP, reviewed

A governance overlay turns a remote MCP server into declared, schema-pinned tools; anything undeclared is never exposed.

Curated and owned

Each connector has an owner, a security review and its own release cadence, so the Runtime core stays small.

Pre-release. 0.2.0a11 is an alpha. A tool's name, input schema, side effect and permission are public contract; any change ships with a CHANGELOG entry and an upgrade note.

Quickstart: add a connector to an agent#

No code is needed for the built-in connectors. Name the plugin, trust the package, enable the tools and grant their permissions.

  1. Declare the plugin in agent.yaml
    agent.yaml
    agents:
  - name: assistant
    version: 1.0.0
    description: Checks that tools are wired up
    system_instructions: Use sample.echo when asked to echo text.
    default_model: {name: m, provider: demo}
    domain_plugins: [algen_agent_tools.sample]   # the connector's plugin
    enabled_tools: [sample.echo]                  # the tools this agent may call
    tool_permissions: [sample.read]               # and their permissions
security:
  trusted_plugin_prefixes: [algen_agent_tools]
  2. Validate it the way Studio will
    zsh
    $ algen-agent-runtime check agent.yaml
$ algen-agent-runtime describe --config agent.yaml --json

    The first command fails on an unknown tool name and suggests the closest match. describe lists each tool with its side effect, permissions, timeout and the environment variables it needs.

  3. Set the connector's environment variables

    Each connector reads its settings from env:// references when its client first opens, never at import. See Secrets and environment.

In Studio, use Add connector instead of writing this by hand. The YAML above is what it writes.

In Studio: add a connector#

When your Studio offers the connector catalog, open the project's Connections tab, go to Tools & knowledge → Connectors, and choose Add on a connector. You can also ask azAI ("let the assistant read my Gmail"); it adds the connector the same way and asks first.

  1. Choose the agents and tools. The connector's default tools are selected. The preview shows what changes: the plugin, the tools and only the permissions they need, the trusted algen_agent_tools prefix, and the sites the connector calls (added to the allowed HTTP hosts, where you can see them).
  2. Fill in its settings. Secrets are saved encrypted and never shown again. A database connector's server must also be declared under Organization → Database hosts before hosted runs reach it.
  3. Build, if Studio says so. Until a build describes the connector, its tools show as Pending build. Where Studio runs catalogued connectors on its own image, no build is needed.

Each connector card shows its maturity (alpha connectors carry a badge), its tools with their side effects, and options only code can set. SMTP cannot run on hosted Studio yet; run it from a local Studio or a deployment. When Studio moves to a newer Tools version, the Connectors section offers Review upgrade, which lists removed tools, new permissions and new settings before anything changes.

Studio's Connectors list comes from the connector catalog of the Tools version Studio ships with, which can be older than the one this page documents. A connector added in a later release appears there once Studio moves to that release.

How it works#

  • A connector is a Runtime Toolkit. Its tools are named <toolkit>.<action> and their permissions sit under the toolkit's prefix (postgres.read, smtp.write).
  • Governance comes from a Runtime preset. read, write, external, destructive or long_running sets the side effect, idempotency, retries, timeout and approval default. Connectors never hand-set them.
  • A plugin registers it. Each connector ships a plugin in the algen_agent_runtime.plugins entry-point group under the trusted prefix algen_agent_tools. Registering opens nothing and resolves no secret.
  • The client opens late. The toolkit's client opens at container start or on first use, resolves its env:// secrets then, and is closed with the container.

Declaring typed queries#

Most agents need the database's own actions. Declare them in your project's plugin:

plugin.py
from pydantic import BaseModel, Field
from algen_agent_runtime.tools.authoring import write
from algen_agent_tools.postgres import PostgresToolkit

class CustomerInvoices(BaseModel):
    customer_id: str = Field(min_length=1)
    due_before: date

billing = PostgresToolkit("billing", dsn="env://BILLING_DATABASE_URL")

billing.query(
    "list_open_invoices",
    "SELECT id, amount, due FROM invoices "
    "WHERE customer_id = $1 AND status = 'open' AND due < $2 ORDER BY due",
    description="List one customer's open invoices that fall due before a date.",
    params=CustomerInvoices,
    row=Invoice,
)

billing.query(
    "add_note",
    "INSERT INTO invoice_notes (invoice_id, text, request_key) VALUES ($1, $2, $3) "
    "ON CONFLICT (request_key) DO NOTHING",
    description="Add a note to an invoice.",
    params=NewNote,
    preset=write(),
    idempotency_key=True,   # the call's key is bound as the last parameter
)
  • params fields fill $1, $2, … in field order; a query whose placeholders do not match is refused when it is declared. Unknown input fields are rejected.
  • A read returns list[row]. A write returns list[row] with RETURNING, otherwise {"rows_affected": n}.
  • preset is any Runtime preset: read() (default), write(approval=...), destructive() (approval on by default), long_running(...).
  • postgres_toolkit(name, dsn=..., schemas=(...)) builds a toolkit that already has the two catalog reads, limited to the schemas you list.

The caller's rows#

In a shared, multi-tenant database, bind the caller's identity with context_params instead of asking the model for it:

plugin.py
billing.query(
    "my_invoices",
    "SELECT id, amount, due FROM invoices "
    "WHERE due < $1 AND tenant_id = $2 AND owner_id = $3 ORDER BY due",
    description="List the signed-in user's invoices that fall due before a date.",
    params=DueBefore,                         # $1, from the model
    row=Invoice,
    context_params=("tenant_id", "user_id"),  # $2, $3, from the call
)
  • The values are ToolContext.tenant_id, user_id, run_id and step_id, which the Runtime sets from the run's authenticated request. Nothing else can be bound.
  • They are not in the tool's input schema, and a call that sends one is rejected. A params field whose name or alias is a context value is refused when the query is declared.
  • Placeholders fill in this order: params fields, then context_params in the order given, then the idempotency key.
  • Caching: the tool declares the bound values as its cache_context, so the Runtime's tool-result cache keys each result on them and never serves one caller's rows to another, at any cache scope. Don't use the session scope for tool results: on Runtime 0.1.0a18 it fails every cacheable call.
  • They narrow rows; they don't replace privileges. Keep a least-privilege role, and use row-level security where the database has it.

The same argument works for MySQL (%s) and SQLite (?) toolkits: all three share algen_agent_tools.sql, and each database adds only a dialect for its placeholders, read-only reads, transactions and timeouts.

Guarantees#

  • No SQL from the model. Inputs are typed fields; values are always bound parameters.
  • Reads cannot write. A read runs in a READ ONLY transaction, so PostgreSQL itself refuses an UPDATE hidden in one.
  • Bounded. Every statement runs under SET LOCAL statement_timeout equal to the tool's timeout. Reads stream through a cursor and fail with TooManyRows, rather than silently truncate, past the row limit (500 by default).
  • Writes are keyed and tried once. With idempotency_key=True the SQL can be exactly-once.
  • The caller's identity comes from the call. context_params values are never tool input, and the result cache keys on them.
  • Catalog reads are limited to the schemas you list and to tables the role can SELECT.

Connect with a database role that has only the privileges the declared queries need.

smtp.send_email takes to (1 to 50), cc, bcc, reply_to, subject, and text_body and/or html_body. It returns the delivery receipt: provider, Message-ID, accepted and rejected recipients.

To reply in a thread, pass in_reply_to (the message_id_header of the message replied to) and references (its references, oldest first), as every mail connector's get_message returns them. They go out as the In-Reply-To and References headers, with in_reply_to added at the end of References. Each is an RFC 5322 Message-ID (<id@host>, at most 980 characters), at most 100 references; anything else is refused before sending.

Sending guarantees (SMTP and Gmail)#

  • The sender is the deployment's. The model cannot choose the From address or add headers.
  • Header-safe. Line breaks in addresses, names or the subject are refused; recipients must be unique, at most 100 in all.
  • One message per idempotency key. The key becomes a deterministic Message-ID and the tool is tried once, so a replay does not send twice.
  • Bounded audience. With allowed_domains, every recipient and the Reply-To address must be in those domains or their subdomains.
  • TLS by default. security is starttls or tls; plain is allowed only to loopback.
  • Content is not captured in audit metadata, and errors name only the failure type.

Attachments are offered only when you configure an artifact loader; see Configure in code.

Quoted history#

From 0.2.0a10, include="latest" on get_message (default "full") and get_thread (default "latest") returns only what the sender wrote: the history the reply quotes and the signature are removed, and quoted_text_removed is set. The rules are deterministic and conservative, so text is removed only after a line that clearly starts quoted history:

  • an attribution line, On <date>, <name> wrote:, also wrapped over two lines and in French, German, Spanish, Italian and Dutch;
  • an Outlook header block (From: then Sent:/Date: and To:/Subject:), or -----Original Message-----;
  • a run of > lines with nothing but blank lines after it (inline answers between quoted lines are kept);
  • a signature after the standard -- line, or a final Sent from my … line.

A forwarded message is new content and is always kept, and a message that is only a quote is returned whole. Gmail and IMAP bodies join every inline text part (at most five), so text a client split around inline images is not lost. The same applies to the Outlook and IMAP toolkits.

Credentials#

Create an OAuth client in Google Cloud, authorise the mailbox once to obtain a refresh token, and grant only the scopes the agent needs: gmail.readonly for list_messages, get_message, get_thread, get_attachment and read_attachment, gmail.send for send_email. The access token is refreshed in memory and never leaves the client; token and API errors name only the failure type.

Reading attachments#

Unread content#

From 0.2.0a8, content the inspection did not read is reported apart from security findings, so a caller can tell "dangerous" from "not read":

  • coverage is full (everything was read), partial (some content was not) or none (content was found but no text could be read). needs_ocr is true when images or scanned pages hold text only OCR can read.
  • Each finding has a category, security or coverage. document.ocr_required, document.images_excluded, document.ocr_no_text, document.truncated, document.attachment_skipped, document.attachment_unread, document.body_unread (an Outlook message whose only body is RTF) and document.pages_skipped (PDF pages past page 50) are coverage findings; only security findings set the disposition.
  • A scanned ID card without OCR is pass with coverage="none" and needs_ocr=true; a cover note over a scan is pass with coverage="partial". Hidden text or an instruction aimed at the model still makes it review or quarantine.

pass with coverage="none" means nothing dangerous was found because nothing was read. Before 0.2.0a8 such documents were review; code that used review to mean "not fully read" checks coverage != "full" instead.

OCR#

OCR is off unless the host passes a recognizer, a TextRecognizer: any object with recognize(image, *, media_type) returning RecognizedText. Pass it as documents_toolkit(ocr=...) or extractor_for(filename, ocr=..., ocr_max_pages=3). The ocr extra ships TesseractRecognizer, backed by the Tesseract program, which the host installs with its languages.

plugin.py
# pip install "algen-agent-tools[documents,ocr]"
from algen_agent_tools.documents import TesseractRecognizer, documents_toolkit

documents = documents_toolkit(
    artifact_loader=load_artifact, ocr=TesseractRecognizer(languages=("eng", "deu"), timeout=30)
)
  • Images (.png, .jpg, .jpeg, .webp, .gif, .bmp, .tif, .tiff) are accepted only with a recognizer, within 40 megapixels and 64 frames.
  • Scanned PDF pages (images and almost no text) are rendered and recognized, up to ocr_max_pages per PDF (default 3); pages past the limit report document.ocr_required.
  • Recognized text is checked like any other. It passes the same prompt-injection checks, so an instruction in a scan quarantines the document. An image or page with no recognized text reports document.ocr_no_text.
  • TesseractRecognizer fails when it is built, naming the fix, if the extra, the program or a language is missing. It is never the default.
  • The recognizer runs inside the tool's 120 s timeout. Images inside DOCX and PPTX are not recognized yet.

OpenDocument#

From 0.2.0a10, ODT, ODS and ODP files (LibreOffice, Google Docs exports) are read with the standard library, with the rules of their Office counterparts.

  • Hidden content is left out and reported: text a style or text:display="none" hides, hidden text fields and paragraphs, text under 2 pt, hidden sheets, rows and columns, and hidden slides.
  • Spreadsheets come out sheet by sheet under --- Sheet: <name> ---, cells joined by | , cut at 5,000 rows per sheet. Comments, tracked changes and speaker notes are not extracted.
  • A Basic macro project, or an image or object loaded from a remote address, is a finding; encrypted files are refused.

RTF#

From 0.2.0a10, RTF is read with a bounded tokenizer from the standard library: paragraphs, tabs and table cells (joined with | ), with escaped and Unicode characters decoded. Font tables, styles, document information, headers, footers and footnotes are not text.

  • Hidden text (\v) and text under 2 pt are left out and reported.
  • An embedded OLE object, a common exploit carrier, is the security finding document.embedded_object; a field that loads a remote file (INCLUDEPICTURE, INCLUDETEXT) is document.external_reference. Pictures are coverage findings.
  • A Word file saved as RTF but named .doc is recognised by its content.

Email files#

From 0.2.0a9 an .eml file is read as its headers (From, To, Cc, Date, Subject) and body, then each attachment's text under an [Attachment: <name>] line, read by the extractor for its type. Attached emails are read at most two levels deep, and at most 20 attachments in the whole message.

  • attachments lists the attachments that were read (file name, media type, disposition, coverage).
  • An attachment's findings are the message's. Hidden text or an instruction in an attachment quarantines the message, and the finding names the attachment in part.
  • Skipped is not refused. An attachment past a limit, of an unsupported type or unreadable is a coverage finding (document.attachment_skipped or document.attachment_unread), so the message is pass with coverage="partial".
  • Outlook .msg files (from 0.2.0a10, with the msg extra, pip install "algen-agent-tools[msg]") are read the same way: Tools reads the sender, recipients, date, subject, body and attachments from the file's OLE streams with olefile, rebuilds the equivalent email and inspects that, with the same limits and findings. Attached Outlook messages are read as attached emails. A message whose only body is RTF reports document.body_unread (coverage), since RTF bodies are not read.

MCP governance overlays#

When a well-maintained MCP server already does what an agent needs, use a governance overlay instead of a native connector. An overlay is a reviewed file, kept in the project, that declares each remote tool the agent may call: its side effect, whether a person must approve every call, and the input schema it was reviewed against. MCP's own annotations (readOnlyHint, destructiveHint) are hints a server sets about itself; the overlay is the deployment's decision.

What an overlay guarantees#

  • Visible before connecting. Each declared tool is an ordinary Runtime tool, so describe and Studio list it with its side effect, permission and approval rule.
  • Deny by default. A remote tool the overlay does not declare is never exposed.
  • Schema pinning. A declared tool that disappeared, or whose input schema changed on the server, is refused until the overlay is reviewed again (on_drift: allow relaxes this).
  • Validated arguments. Arguments are checked against the reviewed schema, with every object closed to unknown fields, before anything is sent.
  • Bounded results. Each tool has a result size limit (256 KB by default) and a timeout.
  • Secrets by reference, hosts pinned. Tokens, headers and a stdio server's environment are env:// references; an HTTP transport may reach only the server's own host unless allowed_hosts says otherwise.

$ python -m pip install --pre 'algen-agent-tools[mcp]'

What every tool guarantees#

Every toolkit in the package passes the same contract harness, algen_agent_tools.testing.assert_toolkit_contract, on top of the Runtime's own tool contract:

  • Narrow and typed. No field, at any depth, takes free-form SQL, URLs, shell commands or vendor request bodies.
  • Honest about what was sent. A call refused before anything was sent, or definitely rejected by the provider, raises an error that is also a ToolNotAttemptedError, so the Runtime records it failed and it can be retried. A timeout or 5xx after a write was sent stays indeterminate for reconciliation.
  • Named and scoped. Every tool is <toolkit>.<action>, and every permission sits under the toolkit's prefix.
  • Governed by a preset. Reads are read(); anything that writes, sends or deletes is write, external or destructive, keyed and single-attempt. Destructive actions require approval by default.
  • Bounded. Timeouts, row counts, page sizes and result bytes all have limits.
  • Content-minimal errors. Errors name the failure type and the field, never the payload or a secret.
  • Outbound hosts are configuration. No tool argument chooses where a request goes.

Attachments: the artifact loader is async def load_artifact(reference, context) -> bytes. The model chooses the artifact id, so the loader must check that it belongs to context.tenant_id (and, if you scope artifacts to runs, context.run_id) before returning bytes.

Saving received files: Gmail, Outlook, IMAP, Telegram and Discord offer <name>.get_attachment only when the toolkit is built with an artifact_sink, the deployment's artifact store. Each file is checked against the attachment_policy (size limit, allowed types, and leading bytes that match the declared type), and the model gets back only the artifact reference, never the bytes.

Write a connector#

Open a "Connector proposal" issue first; a connector needs an accepted proposal. src/algen_agent_tools/sample is the smallest complete connector to copy.

layout
src/algen_agent_tools/<connector>/
  __init__.py   # public API: the toolkit factory, its models and its fake
  toolkit.py    # <connector>_toolkit(...) -> Toolkit
  client.py     # the vendor client; optional imports happen here, lazily
  fake.py       # an in-memory stand-in used by tests
  plugin.py     # <Connector>Plugin = toolkit_plugin("<connector>", ...)
  • The factory takes every setting as an argument, with env:// defaults named ALGEN_TOOLS_<CONNECTOR>_<SETTING>, and a client override for the fake.
  • Tools are defined inside the factory, so each call returns an independent toolkit.
  • Nothing connects in the factory or in register. The client resolves its secrets and imports its optional package when it opens, and raises an error naming the extra if it is missing.
  • The docstring is what the model reads: say what the action does and when to use it.
  • Add an extra and an entry point in pyproject.toml, a docs page, unit tests against the fake, and opt-in live tests.

Connector policy#

The package is curated. A new connector needs all of:

  1. Demand: at least two projects need it.
  2. No domain logic: it speaks to a vendor or protocol, not to one product. Hiring, payroll, text-to-SQL and similar logic belong in a domain pack.
  3. An owner: a named maintainer who reviews its changes and answers its security reports.
  4. A security review recorded in the pull request that adds it.
  5. MCP first: if a well-maintained MCP server covers the need, the package ships an overlay instead. A native connector is justified only when an overlay cannot give a guarantee the agent needs, such as an idempotency key or a typed action the server lacks.

Deprecations warn on use for at least one further minor release before removal, always with the replacement recorded in the changelog.

Troubleshooting#

"Payload transformed by policy" when sending email

The pii guardrail redacted part of the message, usually an address or phone number in the subject or body, and the Runtime does not run a tool on redacted arguments. Recipients are not redacted with algen-agent-tools 0.1.0a2 and Runtime 0.1.0a12 or later, nor are the structured address fields of mail results with 0.2.0a7. Remove the detail from the message, or leave pii out of guardrail_policy.tool_policies; see Email and guardrails.

The plugin is not trusted, or is not found

Add algen_agent_tools (and your own plugin's package) to security.trusted_plugin_prefixes, and check the package is installed in the same environment as the Runtime. algen-agent-runtime describe lists the plugins it can see.

"install algen-agent-tools[...]" when a tool first runs

The connector's optional dependency is missing. Install the extra the message names, for example pip install "algen-agent-tools[postgres]".

An MCP tool is refused after a server update

The server changed the tool's input schema, or removed it. Run snapshot again, review the difference, and update the overlay's input_schema. Use on_drift: allow only when you accept unreviewed changes.

check reports an unknown tool

The name in enabled_tools does not match a registered tool. The message suggests the closest name; tool names are <toolkit>.<action>, so a renamed toolkit renames its tools.

A database read fails with a row limit error

The query returned more rows than its limit (500 by default) and raised TooManyRows. Narrow the query, or raise max_rows when declaring it; reads never truncate silently. This applies to PostgreSQL, MySQL and SQLite alike.

Every cached tool call fails with "Internal error (ValueError)"

The tool-result cache is scoped to session. On Runtime 0.1.0a18 the tool cache gets no session, so every cacheable call fails; Runtime 0.1.0a19 fixed it, and 0.2.0a7 requires 0.1.0a20 or later. On 0.1.0a18 use user or run scope instead. A context_params query is safe at any scope: its cache key includes the values it binds.

Telegram reads fail with error 409

The bot has a webhook, or another program is polling it. getUpdates works only when this connector is the bot's only reader; delete the webhook or use a separate bot.

Discord messages come back with empty text

Turn on the bot's Message Content privileged intent in the Discord developer portal. Without it Discord returns text only for messages that mention the bot.

sender_auth is always unknown on IMAP

On servers other than Gmail, set ALGEN_TOOLS_IMAP_AUTHSERV_ID to the name your receiving server writes at the start of its Authentication-Results header (for example mx.zoho.com). A header the connector can't attribute to your server proves nothing, so it is ignored.
